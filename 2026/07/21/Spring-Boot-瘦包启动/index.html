Spring Boot 瘦包启动：java -Dloader.path 到底在干什么？

踩坑记录：直接 java -jar 报 NoClassDefFoundError: SpringApplication，加一行 -Dloader.path=lib 就好了。这篇把 -Dloader 讲清楚。

一、先从一个报错说起

打包后执行：

报错：

堆栈里出现 PropertiesLauncher.main，说明 JAR 用的是 PropertiesLauncher，不是默认的 JarLauncher。

根因：依赖不在 JAR 里，而在外部的 lib/ 目录。类加载器只扫 JAR 内部，自然找不到 SpringApplication。

二、-Dloader 是什么？

-Dloader 不是 Java 标准参数，而是 Spring Boot Loader 的约定前缀。

写法 含义
-Dloader.path=lib 告诉 PropertiesLauncher：额外从哪些路径加载 classpath
-Dloader.main=com.example.App 指定真正要运行的 main 类（覆盖 MANIFEST 里的 Start-Class）
-Dloader.home=/opt/app 解析 loader.path 相对路径的基准目录

等价配置方式：

  • 环境变量：LOADER_PATH=lib
  • 配置文件：JAR 同目录或 loader.home 下的 loader.properties

注意：-D 参数必须写在 -jar 之前，写在后面会被 JVM 当成应用参数，Launcher 读不到。

三、为什么我的项目需要它？

pom.xml 配置了 瘦包（Thin JAR） 模式：

配合 maven-dependency-plugin 把依赖复制到 target/lib/：

  • JAR 里：业务代码 + Spring Boot Loader
  • lib/ 里：第三方依赖 JAR（如 Spring Boot、MyBatis-Plus 等）

<layout>ZIP</layout> 会使用 PropertiesLauncher 作为 Main-Class，支持运行时通过 loader.path 扩展 classpath——这正是瘦包设计的核心。

七、常见 loader 属性速查

属性 作用 示例
loader.path 额外 classpath lib,./plugins
loader.home 相对路径基准 /opt/vpn
loader.main 覆盖启动类 com.tool.ProxyApplication
loader.config 指定 loader 配置文件 file:./conf/loader.properties
loader.system 是否加入系统 classpath true / false

loader.path 支持：

  • 目录（递归扫描 .jar / .zip）
  • 单个 JAR 文件
  • 通配符
  • 归档内路径，如 deps.jar!/lib

八、瘦包 vs Fat JAR：怎么选？

维度 瘦包 + loader.path Fat JAR（默认）
启动命令 需 -Dloader.path=lib java -jar 即可
部署体积 改业务代码时只替换小 JAR 每次全量替换大 JAR
依赖更新 可单独替换 lib/ 中某个 JAR 需重新打包
运维复杂度 稍高 低

当前项目选瘦包，多半是为了 减小增量发布体积 或 依赖外置管理。若更在意一条命令启动，可去掉 <layout>ZIP</layout> 和空的 <includes>，改回默认 repackage。

九、排查清单

  1. 堆栈里有 PropertiesLauncher？ → 多半要配 loader.path
  2. lib/ 和 JAR 是否同级？ → 相对路径 lib 才能生效
  3. -D 是否在 -jar 前？ → 顺序错了属性不生效
  4. PowerShell 是否给 -D 加了引号？ → 避免参数被截断
  5. 部署是否漏拷 lib/？ → 最常见原因
