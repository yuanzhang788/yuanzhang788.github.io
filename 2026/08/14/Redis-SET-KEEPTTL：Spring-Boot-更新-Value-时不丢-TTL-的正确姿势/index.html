Redis SET KEEPTTL：Spring Boot 更新 Value 时不丢 TTL 的正确姿势

发表于2026-08-14|更新于2026-08-14|后端踩坑记录
|浏览量:

背景

最近在做一个基于 Redis 的访客结账会话缓存：init 时写入 session 快照，默认 TTL 12 分钟；后续绑卡、解绑时会多次 save 更新同一条 key。

设计意图很明确：

  • 新会话：写入并设置 12 分钟过期
  • 已有会话：只更新 JSON 内容，不重置、不取消原有 TTL

听起来很简单，直到我在 Redis 里看到某个 session key 的 TTL 变成了 -1——key 还在，但永不过期了。

补偿定时任务于是反复扫描这个僵尸会话，remove 又一直失败，形成死循环。

Redis TTL 的三个返回值

先对齐语义，避免误判：

TTL key 返回值 含义
> 0 key 存在，N 秒后过期
-1 key 存在，没有设置过期时间（永不过期）
-2 key 不存在

很多人把 -1 理解成「已过期」，其实是反的：-2 才是 key 没了。

问题出在哪：普通 SET 会清掉 TTL

最初的「保留 TTL」写法类似这样：

注释写的是「保留原 TTL」，但 Redis 的普通 SET key value 不会保留过期时间——它会清除 key 上已有的 TTL。

于是实际流程变成：

  1. init：SET key value EX 720 → TTL ≈ 720s
  2. 绑卡后 save：SET key newValue（无 EX）→ TTL 变成 -1
  3. session key 永不过期，补偿任务永远能扫到它

这就是典型的「代码意图和 Redis 语义不一致」。

SET KEEPTTL 是什么

Redis 6.0+ 起，SET 命令支持 KEEPTTL 选项：

KEEPTTL 的作用：更新 value 的同时，保留 key 现有的过期时间。

操作 对 TTL 的影响
SET key value EX 720 新建或覆盖，TTL 重置为 720s
SET key value 覆盖 value，TTL 被清除 → -1
SET key value KEEPTTL 覆盖 value，保留剩余 TTL

Spring Data Redis 怎么用 KEEPTTL

踩的第一个坑：Spring Data Redis 没有高层 API 叫 SetOptions（至少 Boot 3.3 / Spring Data Redis 3.x 里没有这个类）。

正确姿势是走底层 RedisConnection，配合：

  • Expiration.keepTtl() — 对应 KEEPTTL
  • RedisStringCommands.SetOption.UPSERT — 插入或更新

完整分支逻辑：

三种策略对比

策略 session 生命周期 典型问题
每次 set(key, value, 12min) 每次 save 续命 12 分钟 会话可能永不淘汰
普通 set(key, value) 第一次 save 后 TTL 变 -1 僵尸 key 永久驻留
SET KEEPTTL init 起算，12 分钟后自然过期 符合「不续命、不丢 TTL」的设计

边界情况

1. 已经是 TTL=-1 的僵尸 key

KEEPTTL 救不了历史数据——对无 TTL 的 key 用 KEEPTTL，它仍然无 TTL。

此时 remainingTtl == -1 会走 else 分支，用 set(key, json, sessionTtl) 重新补上 TTL，反而是好事。

已存在的僵尸 key 需要手动 DEL 或 EXPIRE key 720。

2. KEEPTTL 不解决业务失败

remove 失败、bound-pins 残留、Apple 会话失效等问题，KEEPTTL 管不了——它只保证 Redis key 会按时消失。

3. 非原子备选方案（不推荐）

两步操作之间有窗口，高并发下可能出问题。优先用 KEEPTTL 一条命令搞定。

如何验证

小结

  • 想在 Redis 里更新 value 但不动 TTL，必须用 SET KEEPTTL，普通 SET 会清掉过期时间。
  • Spring Data Redis 高层 opsForValue().set(key, value) 不会自动 KEEPTTL，需要 Expiration.keepTtl() + 底层 stringCommands().set(...)。
  • 会话缓存类场景：init 设 TTL，后续 save 用 KEEPTTL，是比「每次续命」和「意外变永久 key」都更干净的做法。
