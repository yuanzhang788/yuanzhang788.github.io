使用 GitHub 作为图床：PicGo + Typora 自动上传完整教程

发表于2026-09-15|更新于2026-09-15|技术教程工具配置
|浏览量:

1. 图床的概念

图床就是存储图片、并允许通过公网 URL 访问图片的服务器。

由来：通常我们的图片都保存在本地。比如用 Typora 写的笔记，里面的图片默认都保存在本地。这时候如果我们把笔记发给别人，那么图片也要跟着一起发过去（还得保证路径正确），别人才能完整看到笔记内容。

问题：每次都要把图片和文档一起传来传去，非常麻烦。

解决：如果把图片放到互联网上，任何人都能直接访问和下载，这个问题就完美解决了。这种「别人也能访问到图片」的服务器，我们就叫它图床。

GitHub 仓库 + jsDelivr 免费 CDN，就是一个零成本、稳定的图床方案。

2. 用 GitHub 创建图床服务器

步骤 1：新建仓库

登录 GitHub，新建一个用于存放图片的公开仓库（仓库需为 Public，私有仓库 jsDelivr 无法加速访问）。

步骤 2：生成 Token 令牌

为了让 PicGo 能往仓库里上传图片，我们需要生成一个具有 repo 权限的 Personal Access Token。

进入 GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token。

务必将令牌保存起来，放在一个安全的地方，页面关掉后就看不到了。

步骤 3：创建 img 分支和该分支下的 img 文件夹（可选）

为了和代码分离，建议新建一个 img 分支专门存放图片，并在该分支下创建一个 img 文件夹。

PicGo 客户端下载地址：Releases · Molunerfinn/PicGo

3. 使用 PicGo 软件上传图片

下载并安装 PicGo 后，即可通过软件手动上传图片到 GitHub 仓库。

3.2 配置 PicGo

在 PicGo 的「图床设置 → GitHub 图床」中，需要配置以下基础信息：

  • 仓库名：GitHub用户名/仓库名，例如 username/image-bed
  • 分支名：GitHub 的分支名称，例如 img 或 main
  • Token：GitHub 中生成的 Personal Access Token
  • 存储路径：例如 img/（注意结尾斜杠）
  • 自定义域名：通过 CDN 访问图片的加速域名

自定义域名建议配置为：
https://cdn.jsdelivr.net/gh/用户名/仓库名
或
https://fastly.jsdelivr.net/gh/用户名/仓库名

这样上传成功后，PicGo 返回的链接就会走 jsDelivr CDN 加速，国内访问更稳更快。

4. Typora 实现自动上传

Typora 可以通过调用 PicGo 的接口，在写作时自动把截图/本地图片上传到 GitHub 仓库，并替换为 CDN 链接，从此不再有「图片传不出去」的烦恼。

打开 Typora → 偏好设置 → 图像，做如下配置：

  • 插入图片时选择「上传图片」
  • 勾选「对本地位置的图片应用上述规则」
  • 上传服务选择「PicGo (app)」
  • PicGo 路径填写本地 PicGo 可执行文件的安装路径

配置完成后，可以直接在 Typora 里「右键 → 上传图片」，或使用快捷键验证自动上传是否生效：

小结

至此，一套免费的图床方案就搭建完成了：

  1. GitHub 公开仓库负责存图；
  2. jsDelivr CDN负责全球加速访问；
  3. PicGo负责上传与生成链接；
  4. Typora负责写作时图片自动同步。

无论是写 Hexo 博客还是日常笔记，图片都能一键上云，彻底告别「文档发了图片却丢了」的尴尬。

注意事项

  • 仓库必须为 Public，否则 jsDelivr 无法加速。
  • Token 拥有仓库写入权限，请勿泄露，也不要提交到代码里。
  • jsDelivr 对单文件有大小与缓存策略限制，大图建议压缩后再上传。
